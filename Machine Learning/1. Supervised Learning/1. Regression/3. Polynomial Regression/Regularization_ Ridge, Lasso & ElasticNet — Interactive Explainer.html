Regularization: Ridge, Lasso & ElasticNet Interactive Guide

When a model fits training data too perfectly — memorising every quirk and noise spike instead of learning the actual pattern — it fails on new data. This is overfitting. Regularization fixes it by adding a penalty on large weights, forcing the model to be simpler. Ridge shrinks all weights proportionally. Lasso zeros some weights entirely, acting as automatic feature selection. ElasticNet blends both. Why Overfitting Happens & What Regularization Does

Why Does Overfitting Happen?

A degree-6 polynomial with no constraints discovers combinations like "+500·x⁵ − 500·x⁶" — huge opposite-sign weights that nearly cancel, threading through every training point. Training error → 0, but the curve oscillates wildly. Any new data point will miss it badly.

The Core Idea: A Budget for Your Weights

Regularization adds a second objective: minimise the SIZE of the weights too. Think of it as a weight budget — large weights become expensive, so the optimiser only uses them when they genuinely reduce prediction error enough to justify the cost.

Three Methods, Three Penalty Shapes

  • Ridge (L2): Penalty = α·Σwⱼ². All weights shrink toward zero — none reach exactly zero.
  • Lasso (L1): Penalty = α·Σ|wⱼ|. Some weights snap to exactly zero — automatic feature selection.
  • ElasticNet: Blends both. l1_ratio=1 = Lasso; l1_ratio=0 = Ridge.

The α Parameter

α=0 gives pure OLS (overfitting). Very large α forces all weights to zero (underfitting). Optimal α comes from cross-validation on held-out data — never from training performance alone.

Try: Set Ridge, drag α 0.01→5 — all 6 bars shrink proportionally, none reaching zero. Switch to Lasso — bars snap to exact zero one at a time. That single difference is the entire L1 vs L2 story.

∞ The Three Objective Functions

Ridge (sklearn: no 1/n normalization)
min ||Xw − y||² + α·||w||²
"Minimise total squared error + α × sum of squared weights"
Lasso (sklearn: 1/(2n) normalized)
min (1/2n)||Xw − y||² + α·||w||₁
"Minimise mean squared error + α × sum of absolute weights"
ElasticNet (l1_ratio = ρ)
min (1/2n)||Xw − y||² + α·ρ·||w||₁ + (α/2)·(1−ρ)·||w||²

Key terms: ||w||² = sum of squared weights (Ridge). ||w||₁ = sum of absolute weights (Lasso). α=0 → pure OLS. Large α → all weights near zero.

Note: sklearn's Ridge does not divide by n while Lasso does (1/2n) — a known inconsistency. Always use cross-validation to find optimal α rather than comparing values across methods.

∞ Why Lasso Produces Exact Zeros — Coordinate Descent & Soft Thresholding

Partial correlation (how much feature j "deserves")
ρⱼ = Xⱼᵀ(y − X₋ⱼw₋ⱼ) / n
Soft-threshold update (the "toll booth")
wⱼ ← S(ρⱼ, α) / sⱼ    where S(z,γ) = sign(z)·max(0,|z|−γ)
sⱼ = XⱼᵀXⱼ / n
If |ρⱼ| ≤ α: feature can't "afford the toll" → wⱼ = exactly 0
ElasticNet update
wⱼ ← S(ρⱼ, α·l1_ratio) / (sⱼ + α·(1−l1_ratio))

The "toll booth" intuition: Each feature's weight has "momentum" (ρⱼ). If |ρⱼ| > α, the weight passes through reduced by the toll. If |ρⱼ| ≤ α, the weight is blocked entirely — exactly zero.

Why Ridge never hits zero: Ridge update is simply wⱼ = ρⱼ/(sⱼ+α) — dividing can only shrink, never zero. No threshold, no toll booth, no sparsity.

Step 1 — What Are the Ellipses and the Constraint?

  • Gold dot = OLS solution — the (w₁,w₂) that minimises prediction error with no penalty.
  • Ellipses = MSE loss contours. Smaller = lower error (closer to OLS).
  • Coloured boundary = constraint region. The regularised solution (red dot) is where the smallest ellipse just touches the constraint.

Step 2 — Why Ridge (Circle) Never Gives Zeros

The L2 constraint w₁²+w₂²≤1/α is a perfect circle with no corners. An expanding loss ellipse touches it at a random smooth point — almost certainly where both w₁ and w₂ are non-zero. Ridge can only shrink, never eliminate.

Step 3 — Why Lasso (Diamond) Always Can Give Zeros

The L1 constraint |w₁|+|w₂|≤1/α is a diamond with corners exactly on the axes. Loss ellipses expanding from the OLS solution hit corners preferentially. At a corner, one coordinate is exactly zero. This is geometry, not coincidence.

Step 4 — Why This Scales to High Dimensions

With p features, the L1 ball has 2p corners — one per axis. In high-dimensional problems (p=100), the ball is almost entirely corners. The probability of a loss ellipse touching a corner is very high — explaining why Lasso naturally selects sparse feature subsets.

Compare: Set Lasso (Diamond), drag α to 2.4 — w₂ snaps to zero (check PG 1 bar and PG 2 kink). Switch to Ridge (Circle) at the same α — the red dot slides smoothly, both coordinates remain non-zero throughout.
✦ Key Insight from Playground 3

A zero in PG 1's bar chart = a kink in PG 2's Lasso path = a diamond-corner event in PG 3. These are the same mathematical fact observed from three angles simultaneously.

  • Ridge circle: smooth, no corners → only shrinkage, never zeros.
  • Lasso diamond: corners on axes → zeros snap into existence at specific α thresholds.

When to Use Each Method

Ridge

All features relevant

Default choice. Stable closed-form solution. Handles correlated features by distributing weight across them. No feature selection.

Lasso

Many features, few relevant

High-dimensional settings: genomics, text. Automatic feature elimination produces a sparse, interpretable model. Unstable with highly correlated features.

ElasticNet

Correlated features + sparsity

Lasso arbitrarily picks one from correlated groups. ElasticNet keeps correlated features together (L2) while zeroing irrelevant ones (L1).

CV — Always

Finding optimal α

Training MSE always decreases as α→0. Use RidgeCV, LassoCV, ElasticNetCV — they compute the full path with warm starting efficiently.

Implementation in Scikit-Learn

StandardScaler() before the regularised estimator is mandatory — the penalty applies uniformly to all weights, so unscaled features receive systematically distorted penalties.

Five Consistent Steps

  • 1. Create: PolynomialFeatures(include_bias=False) → StandardScaler() → estimator.
  • 2. Fit: .fit(X_train, y_train)
  • 3. Predict: .predict(X_test)
  • 4. Coefficients: pipeline.named_steps['estimator'].coef_
  • 5. Evaluate: r2_score + np.sqrt(mean_squared_error(...))
import numpy as np
from sklearn.linear_model  import Ridge, Lasso, RidgeCV
from sklearn.preprocessing import PolynomialFeatures, StandardScaler
from sklearn.pipeline      import make_pipeline
from sklearn.metrics       import mean_squared_error, r2_score

ridge = make_pipeline(PolynomialFeatures(degree=6,include_bias=False),StandardScaler(),Ridge(alpha=1.0))
ridge.fit(X_train, y_train)
y_r = ridge.predict(X_test)
print(f"Coef: {ridge.named_steps['ridge'].coef_}")
print(f"R²: {r2_score(y_test,y_r):.4f}  RMSE: {np.sqrt(mean_squared_error(y_test,y_r)):.4f}")

lasso = make_pipeline(PolynomialFeatures(degree=6,include_bias=False),StandardScaler(),Lasso(alpha=0.1))
lasso.fit(X_train, y_train)
y_l = lasso.predict(X_test)
coef = lasso.named_steps['lasso'].coef_
print(f"Non-zero: {np.sum(coef != 0)}/{len(coef)}")
print(f"R²: {r2_score(y_test,y_l):.4f}  RMSE: {np.sqrt(mean_squared_error(y_test,y_l)):.4f}")

rcv = make_pipeline(PolynomialFeatures(degree=6,include_bias=False),StandardScaler(),
    RidgeCV(alphas=np.logspace(-3,3,50),cv=5))
rcv.fit(X_train, y_train)
print(f"Best α: {rcv.named_steps['ridgecv'].alpha_:.4f}")

Critical Pitfalls

1. Not Scaling Features — The Most Common Mistake

The penalty applies uniformly to all weights. A feature measured in thousands needs a tiny coefficient; the penalty barely touches it. A feature measured in fractions needs a large coefficient; the penalty hammers it. Always put StandardScaler() immediately before any regularised model.

2. Choosing α by Training Performance

Training MSE always improves as α→0. Use RidgeCV or LassoCV with a held-out validation set.

3. Lasso with Highly Correlated Features

Lasso arbitrarily picks one from a correlated group. Use ElasticNet when correlated features exist.

4. Treating Coefficients as Feature Importances

Use sklearn.inspection.permutation_importance on a held-out test set for reliable rankings.

5. Regularisation Cannot Fix Wrong Architecture

Treat model architecture and α as separate hyperparameters, both requiring cross-validation.
