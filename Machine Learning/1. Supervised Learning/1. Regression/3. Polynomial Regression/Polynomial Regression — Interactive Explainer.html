How Polynomial Regression Works

  1. Feature Engineering — Create Polynomial Terms: Given a single feature x, generate the vector [x, x², x³, …, xⁿ]. These are the polynomial features. The model is still ŷ = w₀ + w₁x + w₂x² + … + wₙxⁿ — linear in the weights w, even though it is non-linear in x. This is why gradient descent and normal equations still apply unchanged.
  2. Same MSE Loss, More Weights: We minimise the same MSE = (1/N)Σ(ŷ−y)² as in Simple Linear Regression. Gradient descent now updates n+1 weights independently, one for each polynomial term including the bias w₀.
  3. Degree Controls the Shape: Degree 1 = straight line. Degree 2 = parabola (one bend). Degree n = curve with up to n−1 turning points. With the same dataset, higher degree means a more "flexible" and "wiggly" curve.
  4. The Bias-Variance Trade-off: Low degree → high bias (model is too rigid to fit the true curve). High degree → high variance (model memorises every noise spike). The optimal degree is found by evaluating on a held-out validation set, not training data alone.
Try it: Start at Degree 1 — the straight line visibly misses the curve (underfitting). Drag to Degree 2 or 3 to see a parabolic fit snap into place. Detailed Algorithm Explanation

1. Why Polynomial Features? Linearity in Parameters

Polynomial regression is a clever trick: we engineer new features from the original one and then apply standard linear regression. The key insight is that while the relationship between ŷ and x is non-linear, it is perfectly linear in the coefficients w — so all linear regression theory (normal equations, gradient descent, closed-form solutions) still applies exactly.

  • Feature transformation:
    Original: x → Polynomial: [1, x, x², x³, ..., xⁿ]
    ŷ = w₀·1 + w₁·x + w₂·x² + ... + wₙ·xⁿ
  • Gradients remain simple: For each weight wₖ, the gradient of MSE is:
    ∂MSE/∂wₖ = (2/N) Σ(ŷᵢ−yᵢ)·xᵢᵏ
    This is identical to the linear regression gradient, just with xᵏ as the feature.
  • More features = more capacity: Each extra degree adds one new weight. Degree n means n+1 parameters (w₀ through wₙ). With 25 training points, a degree-10 model has 11 parameters — already dangerously close to memorising the data.
  • Feature scaling becomes critical: If x ∈ [1, 10], then x⁸ ∈ [1, 10⁸]. These vastly different scales cause gradient descent to diverge without normalisation. Always standardise polynomial features before fitting.

2. The Bias-Variance Trade-off: Finding Optimal Degree

The central challenge in polynomial regression is choosing the right degree. This is the classic bias-variance trade-off, visualised live in the playground above.

  • High Bias (Underfitting) — Low Degree: A degree-1 line cannot capture a quadratic pattern no matter how much data you have. The model's fundamental form is wrong. Both training and test errors are high.
  • High Variance (Overfitting) — High Degree: A degree-10 polynomial has enough flexibility to pass through every training point. Training error → 0, but the curve oscillates wildly between points. Test error is very high even though training R² ≈ 1.
  • How to find optimal degree:
    • Split data: training + validation sets
    • Fit model for each degree d = 1, 2, 3, ...
    • Choose d that minimises validation error
    • Or use k-fold cross-validation (GridSearchCV)
  • Regularisation as an alternative: Instead of choosing a specific degree, use a high-degree model (say, degree 8) with Ridge or Lasso regularisation. The penalty forces most high-degree weights toward zero, achieving a smooth curve without manually selecting the degree.

Best Use Cases for Polynomial Regression

Manufacturing

Process Optimisation

Many industrial processes have a non-linear optimum — yield peaks at a specific temperature, pressure, or flow rate and falls off on either side. A degree-2 polynomial models this "hill" shape precisely. The fitted parabola's vertex gives the optimal operating point analytically, without running hundreds of expensive physical experiments.

Medicine

Dose-Response Modelling

The effect of a drug as a function of dosage is rarely linear — it typically rises steeply at first, then saturates. A low-degree polynomial (degree 2–3) can approximate this shape. The fitted curve allows pharmacologists to identify the therapeutic range and toxic threshold from a limited number of clinical measurements.

Economics

Diminishing Returns & Production Functions

The Cobb-Douglas production function, diminishing marginal returns, and quadratic cost curves all have polynomial shapes. A degree-2 or degree-3 polynomial fit allows economists to estimate inflection points — the level of capital or labour input at which additional investment starts yielding decreasing returns.

Physics & Engineering

Trajectory & Signal Modelling

Projectile motion is an exact quadratic (s = ut + ½at²). Aerodynamic drag curves, thermodynamic equilibria, and structural deflection under load all follow polynomial relationships derivable from first principles. When the physical law is known to be polynomial, fitting recovers both the prediction and the underlying physical parameters.

Implementation in Scikit-Learn

In sklearn, polynomial regression is built by chaining PolynomialFeatures (feature engineering) with a linear estimator (LinearRegression or Ridge) inside a Pipeline. Set include_bias=False — the linear estimator already adds its own intercept via fit_intercept=True. A StandardScaler between the two steps is essential: x⁸ can be 10⁸× larger than x, making gradient-based optimisers diverge without it.

Key Parameters & When to Use Which

  • PolynomialFeatures(degree, include_bias=False): Generates all polynomial features up to the specified degree. Always set include_bias=False to avoid a redundant column of ones alongside the estimator's own intercept.
  • StandardScaler(): Mandatory between PolynomialFeatures and any regularised estimator. Without it, high-degree features (e.g., x⁸) dwarf low-degree ones, causing Ridge to unfairly penalise them.
  • LinearRegression: No regularisation — use for degree ≤ 3 when data is abundant and the relationship is known to be polynomial.
  • Ridge(alpha): L2 regularisation on the coefficients. Use for degree ≥ 4 to prevent overfitting. Larger alpha = smoother curve, fewer oscillations.
  • Choosing degree: Use GridSearchCV over {'polynomialfeatures__degree': [1,2,...,8]} — never choose based on training R² alone.

Scikit-Learn Code

import numpy as np
from sklearn.preprocessing  import PolynomialFeatures, StandardScaler
from sklearn.linear_model   import LinearRegression, Ridge
from sklearn.pipeline       import make_pipeline
from sklearn.metrics        import mean_squared_error, r2_score

# ── Method 1: Polynomial + OLS (degree ≤ 3) ─────────────

# 1. Create  (include_bias=False: LinearRegression adds its own intercept)
ols = make_pipeline(
    PolynomialFeatures(degree=2, include_bias=False),
    StandardScaler(),
    LinearRegression()
)
# 2. Fit
ols.fit(X_train, y_train)
# 3. Predict
y_pred_ols = ols.predict(X_test)
# 4. Extract coefficients (from the LinearRegression step)
lr_step = ols.named_steps['linearregression']
print(f"Coefficients: {lr_step.coef_}")
print(f"Intercept:    {lr_step.intercept_:.4f}")
# 5. Evaluate
print(f"R²:   {r2_score(y_test, y_pred_ols):.4f}")
print(f"RMSE: {np.sqrt(mean_squared_error(y_test, y_pred_ols)):.4f}")

# ── Method 2: Polynomial + Ridge (high degree) ───────────

# 1. Create  (StandardScaler mandatory before Ridge)
ridge = make_pipeline(
    PolynomialFeatures(degree=6, include_bias=False),
    StandardScaler(),
    Ridge(alpha=1.0)  # L2 penalty — larger alpha = smoother curve
)
# 2. Fit
ridge.fit(X_train, y_train)
# 3. Predict
y_pred_ridge = ridge.predict(X_test)
# 4. Extract coefficients (from the Ridge step)
ridge_step = ridge.named_steps['ridge']
print(f"Coefficients: {ridge_step.coef_}")
print(f"Intercept:    {ridge_step.intercept_:.4f}")
# 5. Evaluate
print(f"R²:   {r2_score(y_test, y_pred_ridge):.4f}")
print(f"RMSE: {np.sqrt(mean_squared_error(y_test, y_pred_ridge)):.4f}")

Crucial Considerations for Polynomial Regression

1. High Training R² Does Not Mean a Good Model — It Often Means Overfitting

A degree-10 polynomial with 20 training points can achieve R² ≈ 1 by threading an oscillating curve through every single data point. This is overfitting — the model has memorised training noise, not learnt the underlying pattern. Test the model on a held-out validation set. If validation R² drops sharply while training R² stays high, you are overfitting. The fix: reduce degree, add Ridge/Lasso regularisation, or collect more data.

2. Feature Scaling Is Mandatory

If x ∈ [1, 10], then x² ∈ [1, 100] and x⁸ ∈ [1, 10⁸]. Without standardisation, gradient descent's step sizes become wildly inconsistent across features. Regularisation (Ridge) is also distorted: it unfairly penalises high-degree weights whose raw magnitudes are small only because they multiply a large feature. Always use StandardScaler() after PolynomialFeatures.

3. Multicollinearity Between Polynomial Terms

x, x², x³ are highly correlated — all three increase monotonically for positive x. This multicollinearity makes the normal equations numerically unstable (near-singular matrix), and causes individual coefficient estimates to be unreliable even if overall predictions are fine. Ridge regularisation mitigates this directly by adding a small positive value to the diagonal of XTX before inversion.

4. Extrapolation Is Extremely Dangerous

High-degree polynomials oscillate violently beyond training data. A degree-8 polynomial fitted to x ∈ [0, 5] may predict a physically impossible value at x = 6. This is far worse than linear extrapolation, which at least maintains a consistent direction. Always explicitly flag and refuse predictions outside the training range for polynomial models.

5. Never Choose Degree Based on Training Performance

Training MSE and R² always improve as degree increases — they are monotonically non-worsening. Choosing the degree that minimises training error would always select the maximum degree, guaranteeing overfitting. Always use a validation set or k-fold cross-validation (GridSearchCV with cv=5) over a range of candidate degrees to find the degree that generalises best.
