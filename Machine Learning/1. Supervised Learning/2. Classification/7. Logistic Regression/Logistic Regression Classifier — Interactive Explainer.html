Logistic Regression Classifier Interactive Guide

Logistic Regression learns a linear decision boundary by maximising the probability of observing the training labels. It is unique among classifiers in this series for outputting calibrated probabilities — not just class labels — by squashing a linear score through the sigmoid function σ(z) = 1/(1 + e−z).

How Logistic Regression Works

  1. Compute the Linear Score: Calculate z = w0x1 + w1x2 + b — a weighted sum of features plus a bias. Positive z pushes toward Dog; negative toward Cat.
  2. Apply the Sigmoid: Transform z into a probability via σ(z) = 1/(1 + e−z). This S-curve squashes any real number into (0, 1). At z = 0 exactly, P(Dog) = 0.5 — the decision boundary.
  3. Decision Rule: Predict Dog if P(Dog) = σ(z) > 0.5 (equivalently z > 0), Cat otherwise. The yellow line on the canvas is exactly where z = 0.
  4. Maximum Likelihood Training: Weights w and bias b are adjusted iteratively to minimise binary cross-entropy loss — maximising the probability of the actual training labels. L2 regularisation (controlled by C) adds a weight-decay term that penalises large weights.
Try it: Drag C to its extremes. Very low C forces a conservative boundary near the data centroid. Very high C lets the boundary hug the training data tightly. Detailed Algorithm Explanation

1. The Sigmoid Function & Log-Odds

The sigmoid maps the unbounded linear score z into a valid probability:

  • Sigmoid formula:
    σ(z) = 1 / (1 + e−z)
    Output always in (0, 1). Differentiable everywhere — essential for gradient optimisation.
  • Log-odds interpretation (the logit):
    log[ P / (1 − P) ] = z = w ⋅ x + b
    The linear score z is exactly the log-odds of class Dog. A unit increase in z multiplies the odds by e ≈ 2.72.
  • Key reference values:
    z = −4 → P ≈ 0.018  |  z = 0 → P = 0.5  |  z = +4 → P ≈ 0.982
  • Probability contours on canvas: z = −ln(3) ≈ −1.10 marks P = 0.25 (red dashed); z = +ln(3) ≈ +1.10 marks P = 0.75 (teal dashed). Points between these lines are in the low-confidence zone.

2. Binary Cross-Entropy Loss & L2 Regularisation

Training minimises a strictly convex loss — guaranteeing a unique global optimum:

  • Binary cross-entropy (negative log-likelihood):
    L = −(1/N) Σ[yi log(σ(zi)) + (1−yi) log(1−σ(zi))]
  • Gradient (elegantly simple):
    ∂L/∂wj = (1/N) Σ (σ(zi) − yi) ⋅ xj,i
    The gradient is just the average prediction error × feature value.
  • L2 regularisation: Augments the gradient with a weight-decay term wj / (C ⋅ N), gently shrinking weights toward zero each step without affecting the bias b (which is never regularised). Larger C → weaker decay; smaller C → stronger decay.
  • Convexity guarantee: Cross-entropy + L2 is strictly convex — any solver converges to the same unique global minimum regardless of initialisation.

Best Use Cases for Logistic Regression

Healthcare

Disease Risk Stratification

Predicting P(malignant) = 0.73 rather than a binary yes/no allows clinicians to apply variable decision thresholds. A high-stakes screening setting might flag all cases with P > 0.1, while a routine check might use P > 0.5. Calibrated probabilities enable this flexibility directly.

Finance

Credit Scoring & Default Probability

Computing P(default | income, debt, history) outputs a continuous risk score rather than a binary approval. Lenders can tier loan conditions by risk band, and regulators can audit the linear decision rule directly through the model coefficients.

NLP & Text

Spam Filtering & Sentiment

Logistic Regression with TF-IDF features is a strong, fast baseline for spam detection, sentiment classification, and topic labelling. As a linear model it handles high-dimensional sparse text vectors efficiently, and each feature coefficient is directly interpretable as a log-odds contribution.

Marketing

Click-Through & Conversion Prediction

P(click | user_features) directly feeds expected-value calculations for ad bidding and budget allocation. The calibrated probability output allows marginal-ROI optimisation — something that requires actual probabilities, not just ranked scores.

Implementation Details & How Scikit-Learn Does It

sklearn's LogisticRegression fits the model via the solver specified by solver — defaulting to L-BFGS, a quasi-Newton method that approximates the Hessian for fast second-order convergence. Unlike Decision Trees, Logistic Regression requires feature scaling — gradient updates scale with feature magnitude, so unscaled features produce disproportionate weight updates.

Key Hyperparameters & Solvers

  • C: Inverse regularisation strength (default = 1.0). Small C = strong regularisation. Large C = weak regularisation (boundary fits training data closely).
  • penalty: 'l2' (default) shrinks all weights. 'l1' induces sparsity. 'elasticnet' combines both. None = no regularisation (will diverge on separable data).
  • solver:
    • 'lbfgs' (default): L2 + None; supports true multinomial. Best general choice.
    • 'liblinear': L1 + L2, One-vs-Rest only. Fast for small binary datasets. Note: uniquely among solvers, liblinear penalises the intercept — use intercept_scaling to mitigate this.
    • 'saga': All penalties including ElasticNet; scales to very large N.
  • max_iter: Default 100 — often too low for real datasets. Set to 1000 to avoid ConvergenceWarning.
  • class_weight: 'balanced' reweights the cross-entropy loss inversely proportional to class frequency, correcting for imbalanced datasets.

Scikit-Learn Example Code

from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline

# LR gradient scales with feature magnitude: always scale
model = make_pipeline(
    StandardScaler(),
    LogisticRegression(
        C=1.0,              # Inverse regularisation (large = less)
        penalty='l2',       # 'l1', 'l2', 'elasticnet', None
        solver='lbfgs',     # L-BFGS: L2/None + multinomial
        max_iter=1000,      # Increase from default 100
        class_weight='balanced',
        random_state=42
    )
)

model.fit(X_train, y_train)
predictions = model.predict(X_test)

# Calibrated probabilities: col 0 = P(Cat), col 1 = P(Dog)
proba = model.predict_proba(X_test)  # shape (N, 2)
p_dog = proba[:, 1]                  # P(class 1 = Dog)

# Log-odds coefficients (one per feature)
lr  = model.named_steps['logisticregression']
w, b = lr.coef_[0], lr.intercept_[0]

Crucial Considerations When Using Logistic Regression

1. Linearity Assumption — Only Linear Decision Boundaries

Logistic Regression can only learn a straight-line boundary in 2D (a hyperplane in N dimensions). If the true boundary is curved, circular, or XOR-shaped (like the Decision Tree dataset in this series), LR will underfit regardless of C. Use PolynomialFeatures preprocessing to create quadratic/interaction terms, or switch to a kernel SVM for genuinely non-linear boundaries.

2. Feature Scaling Is Required

Unlike Decision Trees, LR is sensitive to feature magnitude — the gradient update for each weight is proportional to the feature value: ∂L/∂wj ∝ xj. A salary feature (0–500,000) will dominate a binary flag (0–1), producing enormous weight updates for one dimension. Always apply StandardScaler before fitting.

3. Perfect Separation Causes Divergence

If classes are perfectly linearly separable and C = ∞ (no regularisation), the optimal weights w → ∞ — the model keeps growing weights to push probabilities toward 0 and 1, never converging. sklearn's default C = 1.0 prevents this. penalty=None will diverge on separable data and should never be used without bounded stopping criteria.

4. Class Imbalance Skews the Boundary

The cross-entropy loss averages equally over all N samples. With 95% Class A, 95% of the gradient comes from Class A errors, pushing the boundary toward Class B. The model learns to assign very low P(B) everywhere. Use class_weight='balanced' or threshold adjustment after training.

5. Multicollinearity Inflates Coefficients

Highly correlated features cause unstable, inflated weight estimates — the same loss can be achieved with many weight combinations. L2 regularisation mitigates this by shrinking all weights, but L1 is more principled (zeroing one of two correlated features). For severely correlated inputs, apply PCA or explicit feature selection first.
