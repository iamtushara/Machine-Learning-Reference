How Decision Tree Works

  1. Recursive Binary Splitting: At each internal node the algorithm exhaustively tests every feature and every threshold candidate, selecting the split that most reduces the weighted child impurity (Gini or Entropy — toggle above). The process repeats independently on each child region.
  2. Impurity Measures (toggle to compare):
    • Gini G(t) = 1 − Σpi². Ranges 0 (pure) to 0.5 (max disorder, binary). Faster to compute.
    • Entropy H(t) = −Σpilog2(pi). Ranges 0 (pure) to 1 (max disorder, binary). Penalises mixed nodes slightly more.
    In practice both criteria produce nearly identical trees.
  3. Four Stopping Criteria (in order):
    1. Node is pure (impurity = 0)
    2. Tree has reached Max Depth
    3. Node has fewer than Min Split samples (checked before trying any split)
    4. Every candidate split would leave a child with fewer than Min Leaf samples (checked per split candidate)
  4. Leaf Prediction: A query traverses from root to leaf. The leaf's majority class is the prediction. The prediction card shows the leaf's actual Gini / Entropy value — 0.000 means a perfectly pure leaf.
Try it: At depth 2 the XOR dataset separates perfectly. Increase to 6 to see overfitting. Toggle between Gini and Entropy — boundaries barely change, confirming their equivalence. Then raise Min Leaf to 8 and watch boundaries smooth out as tiny leaves become forbidden.

Detailed Algorithm Explanation

1. Measuring Split Quality: Gini & Entropy

The CART algorithm selects each split by minimising the weighted child impurity:

  • Gini Impurity (default):
    G(t) = 1 − Σi pi2 = 2p0p1
    Ranges 0 (pure) to 0.5 (max disorder for binary). Computationally cheaper — no logarithm required.
  • Entropy (Shannon information gain):
    H(t) = −Σi pi log2(pi)
    Ranges 0 (pure) to 1 (max disorder for binary). Convention: 0 ⋅ log2(0) = 0.
  • Weighted child impurity for a candidate split:
    Isplit = |L|/|N| ⋅ I(L) + |R|/|N| ⋅ I(R)
    The split minimising Isplit is chosen. A pure child (I = 0) contributes nothing.
  • Threshold candidates: midpoints between adjacent sorted unique feature values — exhaustively evaluated per node, per feature.

2. The CART Algorithm & Complexity

CART (Breiman et al., 1984) is the algorithm underlying sklearn's DecisionTreeClassifier:

  • Greedy, depth-first: At each node, test all M features and all threshold candidates, pick the single best split, recurse on each child independently.
  • Stopping criteria — checked in order: (1) node pure, (2) max_depth reached, (3) fewer than min_samples_split samples, (4) no valid split satisfies min_samples_leaf on both children. Any one halts growth.
  • Training complexity: O(N × M × log N) per level — sklearn presorts feature arrays once to avoid repeated sorting.
  • Prediction complexity: O(log N) for balanced trees — traverse from root to leaf.
  • Important: CART is greedy and not globally optimal — a suboptimal depth-0 split can propagate into poor downstream regions.

Best Use Cases for Decision Tree

Healthcare

Clinical Decision Support

Decision Trees produce human-readable if/then rules directly interpretable by clinicians. Used for triage classification, disease risk stratification, and drug dosage recommendation where transparency and auditability are mandatory.

Finance

Credit Risk & Loan Approval

Regulatory frameworks (e.g., GDPR's right to explanation) require justifiable automated decisions. Decision Trees provide exact, traceable rule paths — the preferred interpretable baseline for credit scoring and fraud screening.

Feature Engineering

Feature Importance Analysis

Each split records the weighted impurity decrease it produced. Aggregated across the tree, feature_importances_ is a fast built-in embedded feature selection method requiring no separate computation — works with both Gini and Entropy criteria.

Rule Extraction

Business Rule Generation

Trained trees export as explicit if/else rule sets via sklearn.tree.export_text, converting data-driven models into auditable business logic deployable without any ML runtime infrastructure.

Implementation Details & How Scikit-Learn Does It

sklearn's DecisionTreeClassifier implements CART via an optimised Cython extension. Unlike KNN and SVM, Decision Trees are entirely invariant to feature scaling — splits are raw value comparisons, not distance computations. StandardScaler is not needed.

Key Hyperparameters

  • criterion: 'gini' (default) or 'entropy'/'log_loss'. Near-identical results in practice; Gini is slightly faster to compute.
  • max_depth: The single most impactful regularisation lever. None = unlimited growth = guaranteed overfitting on most datasets.
  • min_samples_split: A node must have at least this many samples before any split is attempted. Prevents splitting on statistically fragile subsets. Default = 2.
  • min_samples_leaf: Every proposed split is rejected if either resulting child would have fewer than this many samples. Ensures statistical stability of leaves. Default = 1.
  • ccp_alpha: Post-growth cost-complexity pruning. Branches whose impurity-reduction-per-extra-leaf falls below this value are removed after full tree construction.
  • class_weight: 'balanced' adjusts impurity calculations inversely proportional to class frequency — corrects for imbalanced datasets.

Scikit-Learn Example Code

from sklearn.tree import DecisionTreeClassifier, plot_tree
import matplotlib.pyplot as plt

# No StandardScaler needed — trees are scale-invariant
clf = DecisionTreeClassifier(
    criterion='gini',        # or 'entropy' / 'log_loss'
    max_depth=4,            # Primary regularisation lever
    min_samples_split=5,    # Node needs ≥5 samples to attempt split
    min_samples_leaf=3,     # Each child must retain ≥3 samples
    class_weight='balanced', # Correct for class imbalance
    ccp_alpha=0.01,          # Post-growth cost-complexity pruning
    random_state=42
)

clf.fit(X_train, y_train)
predictions = clf.predict(X_test)

# Mean impurity-decrease feature importances (Gini or Entropy)
importances = clf.feature_importances_

# Visualise the learned tree
fig, ax = plt.subplots(figsize=(14, 8))
plot_tree(clf, feature_names=feature_names,
          class_names=['Cat', 'Dog'],
          filled=True, rounded=True, ax=ax)

Crucial Considerations When Using Decision Trees

1. Overfitting with Unlimited Depth

An unconstrained tree (max_depth=None, min_samples_leaf=1) creates a leaf for every training sample, achieving 0% training error but catastrophic test error. Always constrain growth using any combination of max_depth, min_samples_split, min_samples_leaf, or ccp_alpha post-pruning. The sliders above demonstrate each effect directly.

2. High Variance / Instability

Adding or removing just a few training points can produce an entirely different tree. Greedy binary splits make all-or-nothing decisions — a slightly different threshold at depth 0 propagates into completely different subtrees below. Use Random Forests (ensembles of trees) to average out this instability.

3. Axis-Aligned Boundaries Only

Splits are always parallel to a feature axis — vertical or horizontal lines in 2D. Diagonal decision boundaries (e.g., x + y > c) or circular regions require an exponentially growing number of splits to approximate. SVM with an RBF kernel handles these geometries directly.

4. Greedy Splits Are Not Globally Optimal

CART selects the locally best split at each node with no lookahead. A suboptimal split at depth 0 might block far better downstream separations. The resulting tree is near-optimal but not globally optimal. Pruning, ensembles, and ccp_alpha mitigate this.

5. Class Imbalance Distorts Impurity

A 90% majority class biases Gini and Entropy calculations, causing the tree to isolate the majority class first and largely ignore the minority. Use class_weight='balanced' or pre-process with SMOTE to rebalance impurity contributions during training.
